# 🧊 Холодильник в общаге (DAC API)

Лабораторная работа № 4 по ПАСЗИ. Реализует бэкенд с дискреционной моделью доступа (DAC) к ресурсам общего холодильника.

---

## 🚀 Стек технологий
- **Python 3.10+ / FastAPI**
- **PostgreSQL + SQLAlchemy**
- **Pydantic, Passlib (Argon2id)**

---

## 🛠️ Инструкция для фронтендера (Локальный запуск)

Если вы хотите запустить бэкенд локально для разработки и тестирования интерфейса:

1. **Перейдите в папку бэкенда:**
   ``` 
   cd backend
   ```

2. **Создайте и активируйте виртуальное окружение:**
    ```
    python -m venv venv
    # Windows:
    venv\Scripts\activate
    # Linux / macOS:
    source venv/bin/activate
    ```

3. **Установите зависимости:**
    ```
    pip install -r requirements.txt

    ```


4. **Создайте файл `.env` в папке `backend/` на основе `.env.example`:**
    ```
    DATABASE_URL=postgresql://postgres:ТВОЙ_ПАРОЛЬ@localhost:5432/fridge_db

    ```


5. **Запустите сервер разработки:**
    ```
    uvicorn app.main:app --reload

    ```


Сервер будет доступен по адресу: `http://127.0.0.1:8000`

---

## 🐳 Запуск через Docker Compose (Альтернатива)

Если у вас установлен Docker, поднять всю инфраструктуру (PostgreSQL + FastAPI бэкенд) вместе можно одной командой из корня проекта:

## Архитектурные особенности для фронтенда

* Авторизация и DAC через заголовок: Вместо токенов проверка прав владельца реализована через передачу идентификатора текущего пользователя в заголовке x_user_id, который бэкенд сопоставляет с полем owner_id в базе данных.

* Логика состояния через описание: Изменение количества или статуса продуктов в текущей реализации завязано на текстовое поле description, а не на отдельную числовую колонку.

* Привязка ресурсов: Каждая запись жестко привязана к создателю через owner_id на уровне моделей SQLAlchemy, что определяет правила дискреционного доступа (DAC).
